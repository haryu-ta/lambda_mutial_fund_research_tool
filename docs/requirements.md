# 要件定義書

## 1. 目的
指定した投資信託の基準価額データを定期取得し、投資判断に必要な情報を LINE に通知する。

## 2. システム概要
- 実行基盤: AWS Lambda
- 起動トリガー: AWS EventBridge（スケジュール実行）
- 取得方式: 外部サイトからのスクレイピング
- 通知方式: LINE Messaging API（Push Message）

## 3. スコープ
- 対象: 複数の投資信託（ISIN / 証券コード等で識別）
- 取得データ: 基準価額、前日比
- 配信先: 指定ユーザーへの LINE 通知

## 4. 機能要件

### 4.1 定期実行
- EventBridge により Lambda を定期実行する。
- スケジュールは cron 式で設定可能とする。
- タイムゾーンは JST とする。
- 既定の実行時刻は平日 09:00（JST）とする。

### 4.2 投資信託データ取得
- EventBridge から Lambda へ、取得対象の投資信託情報（複数）を引き渡す。
- Lambda は対象を 1 件ずつ処理し、以下を取得する。
  - 投資信託名
  - 基準価額
  - 前日比
- 取得元候補サイト（初期想定）:
  - Yahooファイナンス
  - みんかぶ

EventBridgeからLambdaへの引き渡し項目
```json
{
    [
        {id: 2018070301,display_name: "eMAXIS Slim 米国株式"},
        {id: 0331418A,display_name: "ｅＭＡＸＩＳ Ｓｌｉｍ全世界株式（オール・カントリー）（オルカン）"}
    ]
}
```

### 4.3 LINE 通知
- LINE Messaging API の Push Message を利用する。
- 通知対象ユーザーIDは環境変数で管理する。
- 通知はテキスト形式とする。
- 通知メッセージの出力形式は以下とする。
- 通知対象は単一ユーザーとする。

```text
YYYY/MM/DD 基準値
投資信託名1 xx,xxx円 -108円
投資信託名2 xx,xxx円 1円
```

## 5. 非機能要件

### 5.1 エラー処理
- データ取得元サイトまたは LINE API 呼び出しでエラーが発生した場合、CloudWatch Logs に ERROR レベルで出力する。
- エラー発生時は Lambda を異常終了（例外スロー）させる。
- 自動リトライ機能は実装しない。

### 5.2 セキュリティ
- APIキー、トークン、ユーザーIDなどの機密情報はコードにハードコードしない。
- 機密情報は環境変数から読み込む。

### 5.3 ログ
- CloudWatch Logs へ JSON 形式で出力する。
- ログレベルは INFO / ERROR を使い分ける。
- 最低限、以下をログ項目に含める。
  - 実行時刻
  - API レスポンスステータス
  - エラー内容
